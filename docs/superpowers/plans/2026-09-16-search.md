# doccum Keyword Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make everything findable — directory names, file names, property values and the text extracted from documents — ranked, and filtered so nobody sees a result they could not open.

**Architecture:** One projection table, `search_documents`, holds a flattened copy of everything searchable. A `SearchIndex` seam queries it: FTS5 with BM25 ranking on SQLite, a LIKE fallback elsewhere, and room for Postgres tsvector or a hosted engine later. Every document carries the ids of its ancestor directories, so permission filtering is part of the query rather than a pass afterwards.

**Tech Stack:** Laravel 13, Livewire 4, SQLite FTS5, Pest 5.

**Spec:** `docs/superpowers/specs/2026-09-15-doccum-design.md` §8 (search), §5 (access control)

**Previous plans:** foundation, access-control, storage, installer, embedded-storage, properties, extraction — all merged.

## Global Constraints

- **Never edit anything under `vendor/`;** never edit a framework migration.
- `declare(strict_types=1);` on every PHP file authored, migrations included.
- Models use `#[Fillable([...])]`.
- Nothing outside `App\Services\DocumentStorage` resolves a disk; nothing outside `App\Support\ProcessRunner` shells out.
- **Never pass an interface to `toThrow()`** — Pest branches on `class_exists()`, false for interfaces.
- **No result may ever be returned that the viewer could not open.** Permission filtering belongs in the query, never in the view or a post-filter — a post-filter still reveals existence through counts and timing.
- Pest for all tests; each task ends with a green FULL suite and its own commit.
- Baseline entering this plan: **334 tests, 733 assertions**.

Schema::create('search_documents', function (Blueprint $table) {
    $table->id();
    $table->string('subject_type', 32);
    $table->unsignedBigInteger('subject_id');
    $table->string('title', 512);

    $table->unsignedSmallInteger('period_year')->nullable();

    $table->string('mime', 191)->nullable();
    $table->string('extension', 16)->nullable();

    $table->timestamps();

    $table->unique(['subject_type', 'subject_id']);
    $table->index('directory_id');
    $table->index(['period_year', 'period_month']);
});

    indexFile('A.pdf', 'tenant tenant tenant obligations of the tenant');

    $hits = app(SearchIndex::class)->search('tenant', $this->visible);

    app(SearchIndex::class)->put($doc->fresh());

    indexFile('Mine.pdf', 'tenant obligations');

    $hits = app(SearchIndex::class)->search('tenant', $this->visible);

    expect($hits)->toHaveCount(1)
        ->and($hits->first()->title)->toBe('Mine.pdf');

it('returns nothing at all when the viewer can reach nothing', function () {
    indexFile('Lease.pdf', 'tenant');

    expect(app(SearchIndex::class)->search('tenant', []))->toBeEmpty();
});

it('scopes to a period when asked', function () {
    $file = indexFile('Old.pdf', 'tenant');
    App\Models\SearchDocument::where('subject_id', $file->id)->update(['period_year' => 2020]);

    expect(app(SearchIndex::class)->search('tenant', $this->visible, ['period_year' => 2020]))->toHaveCount(1)

it('survives punctuation and quotes in a query', function () {
    // FTS5 has its own query syntax; raw user input must never reach it
    // unescaped, or a stray quote becomes a syntax error in production.
    indexFile('Lease.pdf', 'the tenant shall maintain');

    foreach (['tenant"', 'tenant AND', '"', '(', 'tenant*', 'NEAR('] as $query) {
        expect(fn () => app(SearchIndex::class)->search($query, $this->visible))->not->toThrow(Exception::class);

The last two are the ones that bite in production: an unescaped quote turning
into an FTS5 syntax error, and a permission filter that lets one document
through.

- [ ] **Step 2: Run and watch it fail**

- [ ] **Step 3: Create the FTS5 table**

A migration that creates the virtual table only on SQLite, guarded by the
driver, with `rowid` matching `search_documents.id`:

```sql
CREATE VIRTUAL TABLE search_index USING fts5(title, body, tokenize = 'unicode61');
```

Other drivers skip it and use `LikeSearchIndex`.

- [ ] **Step 4: Implement the seam**

`Fts5SearchIndex` writes with `INSERT OR REPLACE INTO search_index(rowid, title, body)`,
queries with `bm25(search_index, 10.0, 1.0)` so a title match outranks a body
match, joins back to `search_documents` for filtering, and constrains
`ancestor_ids` against the viewable set. **User input is turned into a quoted
FTS5 term list** — each word stripped of syntax characters and wrapped in double
quotes — so no query can be a syntax error or an injection.

Bind the implementation in `DoccumServiceProvider` by driver: `sqlite` gets
FTS5, everything else `LikeSearchIndex`.

## Done when

- Typing a word finds directories, files, property values and text inside documents, ranked with title matches above body matches.
- A user never sees a result they could not open, and a user with no grants sees nothing — filtered in the query, not after it.
- Trashing a file removes it from search immediately.
- Moving a directory updates every descendant's ancestors, so access stays correct beneath it.
- Punctuation, quotes and FTS5 operators in a query are harmless.
- `php artisan test` green; the container still boots clean from empty volumes.
