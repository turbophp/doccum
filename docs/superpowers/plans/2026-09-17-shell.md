# doccum Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the placeholder browser with the real doccum shell — a dense, keyboard-driven, three-pane file manager with drag-and-drop, context menus and the period spine.

**Design plan:** `docs/design/2026-09-17-shell-design.md` — **read it before writing any markup.** It is the authority on palette, type, density, motion, interaction and the component inventory. This plan sequences the work; it does not restate the design.

**Two decisions confirmed by the client:**
1. **Red means "under legal hold" and never danger.** "Move to trash" is a plain `ink` button. Do not introduce a destructive red anywhere.
2. **The backend must enforce what the UI shows.** Task 1 closes the gap before any interface claims protection that does not exist.

**Spec:** `docs/superpowers/specs/2026-09-15-doccum-design.md` §10

## Global Constraints

- Everything in `CLAUDE.md` applies — the seams, the two authorisation layers, the testing rules.
- `declare(strict_types=1);`; models use `#[Fillable]`; registrations in `DoccumServiceProvider`.
- **Never pass an interface to `toThrow()`.**
- **Mutation-check every guard.** Delete it, confirm the test fails, restore it.
- Tailwind 4 is CSS-first: tokens go in the `@theme` block in `resources/css/app.css`. No `tailwind.config.js`.
- Dark and light are both first-class. `prefers-reduced-motion` respected. Keyboard focus visible.
- **Colour may only mean what §1 of the design plan says it means.** A colour used decoratively is a bug.
- Baseline: **432 tests, 902 assertions**.

### Task 1: Make the backend enforce what the UI will show

**Files:** `app/Actions/Files/TrashFile.php`, `RenameFile.php` (new), `MoveFile.php` (new), `app/Policies/FilePolicy.php`, `app/Exceptions/FileIsUnderLegalHold.php` (new)
**Test:** `tests/Feature/Archive/EnforcementTest.php`

A hold that does not stop deletion is decoration. An interface that renders a
red lock over a file anyone can trash is worse than no lock, because it tells
the operator they are protected.

- [ ] **Step 1: Write the failing test**

```php
<?php

declare(strict_types=1);

use App\Actions\Files\TrashFile;
use App\Exceptions\FileIsUnderLegalHold;
use App\Exceptions\PeriodIsArchived;
use App\Models\ArchivePeriod;
use App\Models\File;

it('refuses to trash a file under legal hold', function () {
    $file = File::factory()->create(['legal_hold' => true]);

    expect(fn () => app(TrashFile::class)->handle($file))
        ->toThrow(FileIsUnderLegalHold::class);

    expect(File::withTrashed()->find($file->id)->trashed())->toBeFalse();
});

it('trashes a file that is not held', function () {
    $file = File::factory()->create(['legal_hold' => false]);

    app(TrashFile::class)->handle($file);

    expect(File::withTrashed()->find($file->id)->trashed())->toBeTrue();
});

it('refuses to trash a file in an archived period', function () {
    $file = File::factory()->create(['period_year' => 2024, 'period_month' => 3]);
    ArchivePeriod::factory()->create(['year' => 2024, 'month' => 3, 'archived_at' => now()]);

    expect(fn () => app(TrashFile::class)->handle($file))
        ->toThrow(PeriodIsArchived::class);
});

it('refuses to rename a file in an archived period', function () {
    $file = File::factory()->create(['period_year' => 2024, 'period_month' => 3, 'name' => 'a.txt']);
    ArchivePeriod::factory()->create(['year' => 2024, 'month' => 3, 'archived_at' => now()]);

    expect(fn () => app(App\Actions\Files\RenameFile::class)->handle($file, 'b.txt'))
        ->toThrow(PeriodIsArchived::class);

    expect($file->fresh()->name)->toBe('a.txt');
});

it('refuses to move a file out of an archived period', function () {
    $file = File::factory()->create(['period_year' => 2024, 'period_month' => 3]);
    $elsewhere = App\Models\Directory::factory()->create();
    ArchivePeriod::factory()->create(['year' => 2024, 'month' => 3, 'archived_at' => now()]);

    expect(fn () => app(App\Actions\Files\MoveFile::class)->handle($file, $elsewhere))
        ->toThrow(PeriodIsArchived::class);
});

it('renames and moves a file in an open period', function () {
    $file = File::factory()->create(['period_year' => 2026, 'period_month' => 9, 'name' => 'a.txt']);
    $to = App\Models\Directory::factory()->create();

    app(App\Actions\Files\RenameFile::class)->handle($file, 'b.txt');
    app(App\Actions\Files\MoveFile::class)->handle($file->fresh(), $to);

    expect($file->fresh()->name)->toBe('b.txt')
        ->and($file->fresh()->directory_id)->toBe($to->id);
});

it('refuses to rename onto a name already taken in the directory', function () {
    $dir = App\Models\Directory::factory()->create();
    File::factory()->for($dir, 'directory')->create(['name' => 'taken.txt']);
    $file = File::factory()->for($dir, 'directory')->create(['name' => 'mine.txt']);

    expect(fn () => app(App\Actions\Files\RenameFile::class)->handle($file, 'taken.txt'))
        ->toThrow(App\Exceptions\DuplicateFileName::class);
});
```

- [ ] **Step 2: Run and watch it fail**
- [ ] **Step 3: Implement.** `RenameFile` and `MoveFile` follow the shape of the existing actions: guard, then act, and **do not authorise** — callers do.
- [ ] **Step 4: Add all four guards to `.github/mutations.json`** and confirm `php .github/scripts/mutation-check.php` reports each as load-bearing.
- [ ] **Step 5: Full suite. Commit.**

### Task 2: Foundation — tokens, type, motion helper, shell layout

**Files:** `resources/css/app.css`, `vite.config.js`, `package.json`, `resources/js/shell/motion.js`, `resources/views/layouts/app/shell.blade.php`, `resources/views/layouts/shell.blade.php`
**Test:** `tests/Feature/Shell/ShellLayoutTest.php`

Everything else builds on this, so it lands first and alone.

- [ ] **Step 1: Swap the typeface.** Public Sans 400/500/600 via `bunny()` in `vite.config.js`; `--font-sans` in the `@theme` block. **Verify tabular figures actually work** — render digits in a test page and confirm `font-variant-numeric: tabular-nums` aligns columns. If the Bunny subset lacks `tnum`, fall back to Source Sans 3 and say so in the commit.
- [ ] **Step 2: Add the tokens** from design plan §1 to the `@theme` block: `--sheet`, `--chrome`, `--rule`, `--ink`, `--ink-2`, `--select`, `--hold`, `--attention`, with the `.dark` overrides in `@layer theme`. Keep `--color-accent` bound to `ink` so Flux's buttons stay grey. Override Flux's focus ring and checkbox-checked colour to `select`.
- [ ] **Step 3: Remove the dead `@source` line** pointing at `vendor/livewire/flux-pro` — that package was never installed.
- [ ] **Step 4: Write `resources/js/shell/motion.js`.** Install `motion@^13`. Export `move(el, keyframes, options)` consulting `matchMedia('(prefers-reduced-motion: reduce)')` and returning immediately when reduced, plus the named `springs` from design plan §5. **Every animation in the shell goes through this helper** — no direct `animate()` calls, or reduced-motion is unenforceable.
- [ ] **Step 5: Build the shell layout.** A new `layouts::shell` — full viewport height, no `flux:main` padding, CSS grid: topbar 44px, body 1fr, status bar 24px. The existing `layouts::app` stays for settings and admin pages; only the file browser and search move.
- [ ] **Step 6: Test** that the layout renders for a signed-in user, that both themes resolve their tokens, and that reduced motion is honoured (assert `move()` returns without animating when the query matches).
- [ ] **Step 7: Full suite. Commit.**

### Task 6: Context menus and keyboard

**Files:** `resources/js/shell/menu.js`, `app/Livewire/Files/Actions.php`
**Test:** `tests/Feature/Shell/ActionsTest.php`

Three menus — row, empty space, multi-selection — positioned at the cursor,
opening with **Menu**. Full keyboard table from §6.

**The authorisation rule from §6 is load-bearing and must be tested:** an
action the viewer lacks the *capability* for is **hidden**; an action blocked
by *directory access or file state* is **shown disabled with the reason**.
Hiding the second would leave the operator unable to tell why. Hidden actions
must also be refused server-side — a menu is not an authorisation boundary.

## Done when

- The browser is a real three-pane shell: tree, dense list, detail pane, all resizable and persisted.
- Right-click works on a row, on empty space and on a multi-selection, with unavailable actions hidden or disabled-with-reason per the rule.
- Files drag onto folders and in from the desktop, with a drop target that names where it will land.
- Period bands and the spine make archive status and holds visible without hovering anything.
- Colour appears only where §1 permits it.
- Motion answers actions, honours `prefers-reduced-motion`, and every animation goes through `move()`.
- A held file cannot be trashed; an archived period refuses rename, move and trash.
- Keyboard alone can navigate, select, open, rename and delete.
- `php artisan test` green; the container boots clean; the image smoke test still passes.
